# C-098 紧凑档完成提醒的确认入口：标题行最右端 ✓ 图标按钮（而非迷你文字按钮）

日期: 2026-10-22

#### 上下文
紧凑显示档（`data-density="compact"`）每卡仅保留标题行，当前 R-01-021/AC-02 明确隐藏「移入历史」按钮——完成提醒卡在紧凑档只显示「已完成」胶囊，确认动作（解除提醒、迁入最近历史区）必须先切回中/完整档，索引场景下多一步、断了「看完即收」的动线；但紧凑卡行内宽度极窄（默认 280px 窗格减去两侧 padding），入口形态受空间硬约束。

图标语义预筛（东家参与）：dsh 原生会话的「归档」把会话移出所有列表（垃圾箱语义，东家截图证实），而「移入历史」仅解除完成提醒、卡片留在本窗格最近历史区——两者语义相反，盒/托盘/归档类字形全部不可用；时钟类字形撞历史浏览语义且与窗格历史消息图标撞形；✕ 被读作丢弃；✕ 与「已完成」胶囊撞形是已知代价，但正因撞形反而读得出「我已看完了这个已完成，不再需要看到它」的确认语义。幽灵按钮（透明底无填充、悬停才浮反馈的轻量按钮）形态在方案讨论中向东家解释过。

#### 决策
紧凑档完成提醒卡在标题行最右端（行内右缘信息之后）呈现 ✓ 图标形态的确认按钮：与「已完成」胶囊共用对勾几何，按钮挂可访问名称「移入历史」，显隐由渲染层每帧按档位与 `waitClass` 双条件赋值，激活阻断卡片跳转冒泡并经同一 ack 路由写回（东家拍板，2026-10-22）。

#### 被否方案及原因
- 迷你文字幽灵按钮（agent 建议，四字文案透明底）：字面语义最准，但紧凑行高仅 16px 行框，四字按钮挤压会话标题的可用省略宽度，且与中档收合单行里的文字按钮形成两套同职能形态，视觉重量也高于必要。
- 整卡点击即确认：语义错位——紧凑档激活卡片的既定承诺是跳转会话（R-01-021/AC-04），整卡点击会把「跳转」与「确认」两个动作压在同一交互上，误触成本高。
- 边缘滑动等手势：移动端可发现性差、桌面无对应交互，与现有纯点击交互惯例不符。
- dsh 原生「归档」语义的盒/托盘字形：语义相反（见上下文），且易被读成把卡片移出窗格。

#### 影响面
