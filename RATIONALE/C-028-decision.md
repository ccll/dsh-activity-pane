# C-028 等待状态按阻塞性分两类呈现：阻塞等待脉冲催促、完成提醒静态降噪

日期: 2026-08-26

#### 上下文
东家反馈活动卡片的等待状态标识与描述不够清晰：「需要响应」（回合完成等下一条指令，不阻塞）与「待确认/待审查/待回复」（会话被卡住、不答复就无法继续）性质相反，却共用同一套琥珀色卡面，只能靠读徽标小字区分；且唯一脉冲的是不阻塞的「需要响应」，真正阻塞的三种反而静默，注意力权重倒挂；「需要响应」与「待回复」语义重叠，备注行「等待你的回应（待确认）」只是重复徽标文字，未说清「不答就一直停着」的后果。

#### 决策
- 等待行动按阻塞性分两类：**阻塞等待**（待确认/待审查/待回复）与**完成提醒**（含响应保持），各配一套视觉语言。
  - 阻塞等待卡徽标前置类型图标（对勾/文档/问号气泡）并与标题状态点同频同相脉冲。
  - 完成提醒卡徽标为「已完成」纯文本、不脉冲、状态点静止、描边与光晕弱化。
  - 卡片以 `data-wait="blocked"|"done"` 承载类别。
- 完成提醒标识文案由「需要响应」改为「已完成」；备注行说明动作与后果：阻塞等待为「等待你确认授权/审查计划/回答问题后继续」，待回复卡附问题正文首行（取自时间线末条 ask_user_question 工作项参数），完成提醒为「本轮已完成，等你发送下一条指令」。
- 计数徽标（n/m）分子仍统计全部等待行动主会话，但脉冲改为仅当存在阻塞等待主会话时施加，周期按阻塞等待占比映射——脉冲表达「有会话卡住等你答复」的紧迫感，完成提醒只计数不催促。

#### 被否方案及原因
- 最小改动（仅移动脉冲归属 + 重写作文案，不加图标不改色）：扫视时仍需读字才能区分类别，不满足「一眼区分」的目标。
- 双色系（阻塞橙红、完成绿/蓝）：引入新色相，与「等待=琥珀」的既有主题协调约束（R-01-002/AC-04）冲突面大，且绿易与运行绿、蓝易与当前会话蓝混淆。
- 计数徽标维持「任一等待即脉冲」：完成提醒不阻塞任何事，对其脉冲会把用户注意力从真正卡住的会话上引开。
- 「已完成」卡保留脉冲仅降低频率：仍有动态吸睛，与「不阻塞、可不处理」的语义相悖；静止才是正确的信号。
