# C-043 等待三类语义统一：金色阻塞胶囊、错误提醒红面与「类型胶囊 + 正文」末行结构（修订 C-040 的琥珀色与行尾徽标、C-041 的徽标位置）

日期: 2026-08-27

#### 上下文
一次真实故障暴露语义缺口：某会话内部模型调用持续 429（重试耗尽）而停止，宿主侧把 error 回合的 `turn/end` 与正常回合一样登记 `lastTurnEnd`，活动卡因此显示绿色「已完成」——出错被误报为成功。调查确认错误信号可持久获得（`turn/end` 事件的 `data.reason.kind === 'error'`，已有宿主订阅、acks 通道与 storageDomain 可承载）。东家借机对全部等待状态做统一调整：完成（绿色）、提问（金色）、出错（红色）三类语义，且末行统一为「类型胶囊 + 正文」结构。

#### 决策
- 等待行动扩为三类 `waitClass`：`'blocked'` 阻塞等待（金色）、`'done'` 完成提醒（绿色）、`'error'` 错误提醒（红色，新增）。
  - 错误红与时间线错误分组行同源 `#f06a72`；金色自琥珀 `#e8a33d` 调亮调纯而来。
  - 三类描边/光晕/状态点强度与深浅主题沿用既有结构。
- 末行统一「类型胶囊 + 正文」：首行为类型胶囊（圆形底类型图标 + 类型文字）——阻塞为待确认（对勾）/待审查（文档）/问题（问号）金胶囊、完成为绿对勾「已完成」胶囊、错误为红感叹号「错误」胶囊；胶囊与正文同频同相闪烁（dap-pulse 1.2s，沿用 data-wait 相位重启），「移入历史」按钮不闪。
- 错误提醒成立 = 主会话 && 非 running && 无阻塞等待 && 非委托周期 && `lastTurnEndKind === 'error'`；随新回合结束（lastTurnEndKind 覆盖）解除，不消费 ack 游标、不提供按钮。
  - 经 acks 通道持久化（记录 `lastTurnEndKind` 与截断的错误信息 `lastTurnEndError`），刷新/重连恢复。
- 数量徽标底色按 错误 > 阻塞 > 完成 优先级取色（红/金/绿）。
- 待确认、待审查与待回复同归金色阻塞类（东家裁定统一）；提问 Q 行列表保留「Q1: …」编号前缀（C-041/C-042 口径不变）。

#### 被否方案及原因
- 维持双类现状、不引入错误类：429 场景实测误报成功，正是本决策的直接动因。
- 错误信号用 `ConversationSnapshot.lastAgentError`（host/agent-error 帧）：仅连接活跃期间可达、刷新即丢（宿主不重放），不能作为持久状态；`turn/end` reason 是持久日志，唯一可靠来源。
- 错误卡提供「移入历史」按钮：东家裁定错误卡不设确认按钮，红色提醒随新回合覆盖解除即可（会话仍可对话）。
- 问题列表去掉编号只列正文：保留 Qn: 编号可与原生提问对话框序号对应（C-042 前提），东家裁定保留。
- 徽标底色多色并列或按多数取色：单色徽标无法表达混合构成的最高紧迫信号，按紧迫度优先级取色是既有「取最紧迫」思路的延伸。
- 待确认/待审查保持琥珀+行尾徽标旧式：破坏「胶囊 + 正文」统一模式，三类视觉语言分裂。
