# C-076 卡片紧凑显示以常显悬浮切换承载全体收缩，而非标题行控件或逐卡折叠

日期: 2026-09-15

#### 上下文
完成后的会话卡留在活动区等待后续继续执行时，卡片的时间线、统计与等待末行持续占用屏面，干扰观察、寻找与定位其余会话。候选交互有整卡手动折叠（东家原案的悬停变光标 + 首行点击）、标题行行尾嵌套切换、完成后自动紧凑与全局一键收缩四族；落位候选有窗格标题行行尾、header 下独立工具行、右下角悬浮与左下角悬浮。

#### 决策
在「回到顶部」按钮正上方常显一枚同规格纯图标 toggle，一键在完整呈现与紧凑呈现（每卡仅保留标题行）之间切换；作用范围为活动区与历史区全体卡片（含运行卡与等待卡，类别底色与状态点着色保留），选择存 localStorage 并在刷新后恢复，会话状态变化不解除已选形态。

#### 被否方案及原因
- 悬停变光标 + 首行点击折叠：卡片首行已是跳转激活区（role=button），嵌套点击目标误触率高；纯 hover 光标是隐形可供性，发现性差。
- 标题行行尾嵌套切换：标题行整体已是窗格折叠控件（R-01-011），两个「折叠」语义同行难辨对象，且需改写 R-01-011 的整行激活语义。
- 完成后自动紧凑：卡片结构随状态自动变形不可判定、易产生阅读中断；手动切换语义确定且可持久化。
- header 下独立工具行/左下角悬浮：前者为一个按钮生造一行、与省空间初衷矛盾；左下角为次要角落、发现性差且常显遮挡更持久。
- 豁免运行卡与等待卡（仅冷卡收缩）：列表高度混合打断扫描；等待紧迫度已由卡面类别色、状态点与列头脉冲徽标承载，全体收缩后仍可辨识。

#### 影响面
R-01-021 / 窗格渲染器；DOMAIN「紧凑显示」术语
