# C-088 移动端「活动」开关呈紧凑形态（图标+计数徽标），并显式钉死按钮宽度

日期: 2026-10-10

#### 上下文
T-160 嵌入标题行后，东家真机实测反馈「胶囊太大太长」：真机截图量得胶囊宽 ~160pt，而内容（文案+徽标）仅占一半、右缘 ~93pt 空白，Chromium 复现不出——引擎（iOS WebKit）相关的按钮内在尺寸差异未被现有 CSS 约束；且「活动」文字标签使胶囊固有宽度 ~80px，在拥挤头部中持续挤压会话标题。

#### 决策
开关呈紧凑形态（面板图标 + 计数徽标，不显示文字标签），并显式钉死按钮宽度：`width:max-content` 加 `appearance:none`，嵌入态与兜底态同口径；东家指示即需求变更确认，AC-04 文案条款同步修订。

#### 被否方案及原因
- 迁位到会话头部 tabs 行右端：东家明确否决了「头部太挤」的前提判断（「不是太挤，是胶囊太大太长了」），迁位还要修订位置条款且窄视口余量不足（390pt 实测余 85px，完整胶囊 80px 加行间距溢出）。
- 仅修宽度拉伸、保留文字标签：胶囊仍有 ~80px 固有宽，继续挤压会话标题至不可见下限，东家的形态反馈得不到回应。
- 回退浮层：遮挡问题回到 T-160 之前，与东家「嵌入布局」的原诉求相悖。
- 徽标单挂（去掉图标只留计数）：宽度最小但语义不可辨，一眼不知按钮归属。

#### 影响面
R-01-008 / 窗格渲染器（T-161）
