# C-035 时间线名额先保真实当前活动行，history 锚行并入核心单次选择（修订 C-023）

日期: 2026-08-26

#### 上下文
C-023 把指令锚行纳入四行总预算后采用「锚行 + 数组末三行」裁剪；1822e9cd4f0ad021f50957d50630ab97b796019c 又在核心派生完成后由 client 以 history 锚行执行第二次同类裁剪。实测与纯函数复现证明：真实 running 行位于四工作行首位、其后有三条 done 行时，前者会被裁掉并由旧尾行冒充活动；client 后置裁剪还会在无再提升机会时把蓝闪活动状态完全删除。东家明确时间线契约为总计最多四行、首行为指令、其后最近最多三工作行，真实当前活动内容必须保留在末行。

#### 决策
- 指令锚行占一个总预算名额，工作行预算固定为最多三个；更近用户输入直接取代旧锚，不额外减少工作行名额。
- live partial/running call 以内部身份穿透折叠层。
  - 窗口选择先保留最新真实当前活动行并置于末行，再用最近历史工作行填满其余名额。
  - 没有真实活动行时才允许尾部提升。
- history 锚行作为核心时间线派生的输入参与同一次选择；删除 client 派生后的二次裁剪，渲染层只消费最终行序列。

#### 被否方案及原因
- 保留末三行裁剪、裁后再运行一次尾部提升：只能让旧尾内容变蓝，无法恢复被删除的真实活动文字。
- 继续允许 client 后置 `withInstructionAnchor`：同一预算规则存在两个出口，真实活动身份可在第二次裁剪中丢失。
- 恢复锚行之外额外四工作行：总计五行，重复 C-023 已由东家否定的过密呈现。

#### 影响面
R-01-009、R-01-012、R-01-017 / 活动状态模型、窗格渲染器
