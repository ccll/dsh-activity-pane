# C-034 七色锚点改用 OKLCH 感知调色板，撞槽由相邻探测改为步进 3 跨色区探测（修订 C-033）

日期: 2026-08-26

#### 上下文
C-033 上线后东家实测：`docsim` 与 `dsh-activity-pane` 仍显得接近，一个偏绿、另一个绿中带橙，而 `ops` 偏蓝且距离较远。查证当前路径映射：`docsim` 与 `dsh-activity-pane` 的稳定基色都落到起始槽 0，后者按相邻 `+1` 探测，被刻意分配到相邻 HSL 锚点 30°/78°；同时 HSL 色相角并非感知均匀距离，固定 S/L 与 currentColor 混色进一步冲淡了分类差异。

#### 决策
- 显示色相改为七个避红 OKLCH hue 锚点 `[55,100,145,190,235,280,325]`，在共同 L/C 下最小 hue 间距 45°；深色文字用 L 0.78 / C 0.16，浅色文字用 L 0.48 / C 0.15，最小 OKLab 距离分别约 0.122 / 0.115。
- 撞槽探测由相邻 `+1` 改为跨色区 `+3`；3 与 7 互质，顺序 `0→3→6→2→5→1→4` 可遍历全部槽，首次冲突跨约 135°。
  - 当前路径因此映射为 `docsim` 55°（橙）、`dsh-activity-pane` 190°（青）、`ops` 280°（蓝紫）。
- 文字直接使用 `oklch(...)` 调色板色，不再混入 currentColor；背景与描边改用 `color-mix(in oklch, …, transparent)`。
  - 深色底/边为 14%/34%，浅色为 10%/28%。

#### 被否方案及原因
- 只把 HSL 换成 OKLCH、保留相邻探测：可改善色彩均匀性，但同起始槽的工作区仍被分配为相邻分类色，无法根治东家观察到的问题。
- 只改探测步进、保留 HSL：能拉开撞槽身份，但 HSL 的数值角距离仍不等于人眼感知距离，且 currentColor 混色继续造成发灰偏色。
- 为每个工作区硬编码颜色：当前三个工作区会很好看，但新增/删除工作区时不可扩展，违背自动分配目标。
