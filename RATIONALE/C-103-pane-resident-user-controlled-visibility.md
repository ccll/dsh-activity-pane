# C-103 页面切换期间桌面窗格常驻，不再自动收起

日期: 2026-11-17

#### 上下文
东家在日常使用中发现：从会话页切到插件页、插件市场等全局面板后，活动会话窗格消失，只有选回一个会话才重新出现；希望窗格固定依附在左边栏右侧，切页时保持用户当前的展开/收起形态。隔离探针（dsh 0.2.0-rc.2）确认窗格节点并未被宿主卸载，而是插件在全局面板分支主动写入 `display:none`（判据为宿主 `data-global-panel` 标记或会话滚动区缺失）。该行为源自 C-101 的方案 A（2026-11-16 拍板）：当时以「全局面板占满主区域」为优先，实测保留窗格时内置 Plugins 页只剩 720px，故否决常驻。本次东家明确改变取舍：窗格是活动会话总览，切页期间保持可见比面板全宽更重要，且窗格自身已有标题行折叠控件，无需代码代为判断。新证据：1280×800 下折叠态窗格 34px、面板剩 966px；展开态 280px、面板剩 720px；1024×768 面板剩 464px；768×900（侧栏收为 56px 图标条）面板剩 432px，内置插件页均保持可读。

#### 决策
在会话视图与全局面板之间的页面切换期间，桌面窗格常驻于外壳侧栏右侧，显隐与展开/收起形态保持不变；代码不再按全局面板标记或会话视图缺失自动隐藏窗格。全局面板占据窗格右侧剩余主区域而非全宽（东家拍板，2026-11-17，T-197）。

#### 被否方案及原因
- 沿用方案 A（全局面板占屏时自动收起窗格）：现有承诺与实现，代价是切页即失去活动会话总览，与东家本次诉求直接冲突；面板全宽的收益不足以抵消窗格消失。
- 把窗格挂到外壳 frame 层并以绝对定位独立于中列：语义上彻底脱离会话页，但实测 absolute 后窗格宽度从 flex 宽度塌成内容宽，需要重新接管侧栏拖拽/折叠动画、rightbar 全屏、窗口缩放、折叠窄条与指针层级，改动面 150–300 行且视觉与保留中列等价，收益不抵风险。
- 宽视口常驻、窄视口（如 <1024）仍自动收起：多保留一条自动判据，违反「显隐只交给用户」的本次要求；768 宽度实测面板 432px 仍可读，不需该例外。
- 保留窗格但收缩为窄条并禁止展开：窄条仍占宽，且全局面板期间用户无法操作窗格内容，收益低于常驻并接受面板让宽。

#### 影响面
R-01-007 · 窗格渲染器（T-197）
