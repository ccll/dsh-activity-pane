# C-020 历史区时间口径：插件侧以 turn/end 精化最后活动时间，取代宿主 updatedAt 口径

日期: 2026-08-26

#### 上下文
东家发现最近历史卡的「最近 xx:xx」显示的是宿主 `updatedAt`（会话创建时刻与最后一条真人用户消息时刻的较新者），而非会话真正最后更新的时刻；agent 回复结束、工具运行均不推进该值。东家判定「最后 agent 回复结束时刻」才是真实最后更新时间，要求历史区判定、排序与显示改用该口径。

#### 决策
- DOMAIN 重定义「最后活动时间」：最后一轮回复结束时刻与宿主列表时间的较新者。
  - 无已完成回合时即宿主列表时间。
  - 冷会话数据在途时先以宿主列表时间参与判定/排序/显示，到达后取较新者精化。
- 冷会话复用既有 history 拉取的同批事件提取最后 `turn/end.time`（不新增请求、不扩大深翻预算）；热会话取 `turnTimings` 最大 `endTime`。
  - `buildRecent` 新增 `turnEnds` 入参归一 max。
  - 条目字段 `updatedAt` 改名 `activityAt`。
- 接受跨窗长回合缺口：宿主时间已超窗的会话不读取历史，其窗内回合结束时刻不可知、不入历史区。

#### 被否方案及原因
- 沿用宿主 `updatedAt` 口径：东家判定其失真——只反映发消息/创建时刻，回复跑多久都不推进。
- 严格只取回合结束时刻（不取较新者）：用户发消息后回合未结束（排队/立即中断）时最后用户消息本身即更新，回退到更早回合结束时刻反而更旧。
- 对超窗会话全量拉 history 消除跨窗缺口：需对所有超 24h 会话发起历史读取，违背「轻量常驻、有界读取」纪律，成本不抵边缘收益。
- 推动宿主修改 `updatedAt` 语义：宿主为上游 DSH，语义变更越出本仓库边界，且列表排序等其他消费方依赖现语义。

#### 影响面
