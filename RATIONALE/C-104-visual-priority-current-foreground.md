# C-104 视觉优先级：当前会话前台态最高、后台态次之、等待提醒卡不压过二者

日期: 2026-11-20

#### 上下文

T-197 让窗格跨页面常驻后，同一屏里同时出现三类卡片：当前会话（细蓝描边）、等待提醒三类（整卡彩色铺底 + 高 α 彩色描边）、普通活动卡。东家反馈完成提醒的绿底绿边「太醒目、喧宾夺主」，一眼找不到当前会话在哪里；同时确认卡在面板页仍高亮但激活无效（同一批修复，见 R-01-006/AC-03～AC-04）。既有的 C-040/C-043 只定义了等待三类的色相语义，没有定义它们与当前会话高亮之间的强度关系。

#### 决策

把「强调预算」从面积改为形状：当前会话前台态以 1.5px 外环 + 16px 外光晕 + 内发光成为窗格最高视觉层（深色亮蓝 `#8fbcff`、浅色深蓝 `#2f7cf6`，浅色底上亮蓝对比不足）；后台态保留同色相、降为弱化描边与外环；等待三类卡保留色相语义，但底色向活动卡底色收窄、描边与外环降权、投影减弱，整体不压过前台态。判定「正在查看」由选中会话与 `layout.panelInfo.activePanelId === null` 两维共同承载，卡片 `data-current` 保持选中语义、新增 `data-foreground` 承载在屏语义。

#### 被否方案及原因

- 只提高当前会话、不动等待卡：完成提醒整卡铺色的面积优势仍在，同屏依旧抢眼；完成提醒数量累积时的绿色噪声也不减。
- 只降低等待卡、不动当前会话：当前卡仍只有一圈细描边，缺少一眼定位的形状线索。
- 前台态与后台态用不同色相（后台转灰）：丢掉「同一会话只是不在前台」的连续性，也与宿主原生会话列表的选中蓝不一致。
- 面板页取消当前会话高亮：宿主原生会话树在面板页仍标记选中，窗格若取消会与外壳矛盾，并丢失「我上次在哪」的位置信息。
- 扩大 `.dap-list` 横向内边距以容纳更大外光晕：会缩窄全部卡片，牵动紧凑档断点与轨道线测量；改用内发光与外环承载可见的「发光」。
