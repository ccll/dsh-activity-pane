# C-078 阻塞等待会话排序键改取等待边界开启时刻（修订 T-133 口径在阻塞等待场景的适用）

日期: 2026-09-16

#### 上下文
T-133 把等待/完成组的排序口径统一为「进入状态时刻 = 最近一次回合结束登记时刻（`lastTurnEnd`）」，隐含「回合已结束」假设。docsim 实测（2026-09-16）暴露阻塞等待场景失效：会话 19:22:32 进入提问等待（本回合未结束），`lastTurnEnd` 停留在 15:07:44 的上一回合登记，刚提问的会话在等待组被压到末位、晚于数小时前完成的会话。

#### 决策
阻塞等待会话的排序键改取回合内等待边界开启时刻（宿主回合记账 `openWaitStart`，经既有 R-01-020 SSE 通道以 `buildEntries` 新入参 `waitingStarts` 注入）；完成提醒/错误提醒维持 `lastTurnEnd`；两者缺失均回落宿主列表时间，且不以 `lastTurnEnd` 作为阻塞等待会话的中间回退。

#### 被否方案及原因
- 宿主在 `pendingInteraction` 出现时向 acks 表新登记进入时刻：需新增持久化字段与生命周期管理，而 `openWaitStart` 已存在、已随既有通道全量推送，复用零新增成本。
- 以 `lastTurnEnd` 作为阻塞等待会话的中间回退：对等待进行中的会话正是本缺陷根因（语义错误的旧时刻）；宿主列表时间（最后用户指令时刻）恒不晚于进入等待时刻，作为回退更接近意图。

#### 影响面
R-01-001/AC-07 · 活动状态模型
