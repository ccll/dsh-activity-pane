# C-082 达标类性能收敛按 map 不变短路处理，量化守恒由浏览器功耗门禁承载

日期: 2026-09-22

#### 上下文
AGENTS.md 性能优化入口规则要求「PRD 目标已在则 map 不变，无目标先补承诺；基准测试；无基线不动手」。T-127/T-128 一类变更——不改变任何可观察行为承诺、仅消除已确认的逐帧重绘或合成外动画源——在历史上按 map 不变短路处理：PRD 无性能类承诺、无前后对比基准，双轴审核（T-128 检验）指出该实践与规则文本冲突。同时，把「合成器驱动」等实现机制写进 PRD 与 PRD 判归属（机制不写入）冲突；且 T-127 起移动端功耗已有可量化、可判定的浏览器 E2E 门禁（移动端热静默 spec 的 rAF 请求次数阈值断言）随每次全量验证执行，构成事实上的守恒基线。

#### 决策
经东家确认（2026-09-22）：不改变可观察行为、目标为消除已确认重绘/耗电源的「达标类性能收敛」按 map 不变短路处理，PRD 不增设机制类性能承诺；其量化守恒由既有浏览器功耗门禁（移动端热静默 E2E 的 rAF 请求次数阈值断言，随全量验证执行）承载；此类 task 关闭时须在终态记录与该门禁的对照关系及行为守恒证据。

#### 被否方案及原因
- 为此类变更在 PRD 补机制类性能承诺（走全链）：机制不属 PRD 判归属范围，承诺随实现机制演进很快失真。
- 要求每次此类变更补前后基准测量：行为守恒证据已由功耗门禁与全量回归承载，重复基准的边际价值低于成本。
- 维持现状不留痕：规则文本与实践的冲突会持续触发审核发现，属应记录而未记录的过程解释。

#### 影响面
过程规范（CONVENTIONS 承载的解释性决策；PRD 需求无变化；源于 T-128 检验）
