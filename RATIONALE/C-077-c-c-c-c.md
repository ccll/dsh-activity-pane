# C-077 工作区徽标颜色槽位改为逐身份纯映射，放弃同屏唯一性（修订 C-033、C-034、C-072、C-073 的集合级分配）

日期: 2026-09-15

#### 上下文
C-033/C-034/C-072/C-073 的槽位分配以「当帧可见身份集合」为输入做贪心消解（uses 计数 + 未用优先），保证同屏 ≤12 个身份时槽位唯一。实例中新建一个工作区后，既有全部工作区卡片的胶囊颜色随之改变——贪心的「未用槽位」依赖集合构成，任何新增身份都会重排既有身份的槽位，颜色失去「每个工作区一个固定颜色」的归属记忆价值。东家确认：颜色必须由工作区自身稳定派生，与工作区总数及其它工作区无关；允许碰撞，但应尽量少。

#### 决策
`resolveWorkspaceColors(keys)` 改为逐身份纯映射，集合只是批量入口：每个身份独立以其 32 位雪崩哈希派生——前景取 `workspaceHue` 基色在 12 个 OKLCH 前景槽位中环形色相距离最近者（平局取低槽位），背景变体取 `floor(hash / 291) % 3`。同屏唯一性与「未用背景变体优先」语义废止；12 槽 OKLCH 调色板、避红约束与 OKLab ≥ 0.11 感知距离约束不变；碰撞概率经均匀哈希保持在约 1/12（前景）、1/36（复合）的最小水平。

#### 被否方案及原因
- 保持集合级消解 + 为每个工作区持久化登记初次槽位：颜色稳定但引入注册表、回收与跨端同步问题（C-072/C-073 已否决持久化），清数据或换机后颜色仍会漂移。
- 哈希直接 `hash % 12` 取槽：绕开基色色相，AC-09 的避红弧取色语义与 C-029 的哈希叙事脱节；就近归槽的桶宽与槽位间距同阶，碰撞率同为 ~1/12 且保留基色语义。
- 增量分配（已有身份槽位冻结、新身份避开已用）：冻结状态同样需要持久化，且集合仍是隐式状态，未根治。
