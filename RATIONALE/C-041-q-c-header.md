# C-041 待回复卡末行改提问 Q 行列表（修订 C-040 的首问 header 子决定）

日期: 2026-08-27

#### 上下文
C-040 落地后待回复卡末行显示首问 `header` 短标题（如「演示选择」）。东家实测认为短标题不能体现所问的问题内容，希望末行直接列出全部提问正文；并给出格式裁定：每条一行、序号前缀 Qn:，仅一条问题时前缀简化为「Q：」不带编号，行尾多余冒号不显示，最多 3 条其后以省略行收尾；同时徽标文字自「待回复」改为「问题」（图标不变）。

#### 决策
- 待回复卡末行改为逐条列出提问正文的 Q 行列表：`askQuestionsPreview` 从时间线末条 ask_user_question 工作项参数解析全部问题，逐条取正文物理首行（缺失回落该条 header，仍不可得跳过该条）、剥除行尾多余冒号，输出「Q1: …\nQ2: …」多行文本。
  - 仅一条时前缀为「Q：」。
  - 最多 3 条，其后以省略行「…」收尾。
  - 全部不可得回落动作说明。
- 末行文字容器改 `white-space: pre-line` 承载多行（完成提醒/recent 单行用途不受影响）。
- 徽标文字改「问题」，类型图标（问号气泡）不变；类型概念「待回复」在文档与注释中保留。

#### 被否方案及原因
- 维持 C-040 的首问 header 短标题：东家实测「演示选择」式短标题不体现问题内容，提示价值不足，本决策的直接动因。
- 多问题拼接为单行文本：单行省略会吃光多问内容，卡片宽度无法承载「Q1+Q2」全文，多行分行是唯一能完整呈现多个问题的方案。
- 每问行取 header 优先：header 是提问卡头字段而非问题本身，用户要看的是所问内容（`question` 字段）。
- 不设 3 条上限：超长问题列表撑爆卡片高度，3 条 + 省略行是社会对话场景的合理呈现上界（东家裁定）。
