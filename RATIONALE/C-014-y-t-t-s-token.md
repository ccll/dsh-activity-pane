# C-014 运行卡进度改由本回合已耗时经有理曲线 y=t/(t+120s) 驱动，替代 token 累计饱和曲线

日期: 2026-08-24

#### 上下文
运行卡进度原由「阶段 + 输出 token 累计」估计（C-005），但 `tokenUsage` 投影只在 usage 事件（`assistant/chunk` 的 usage chunk / `assistant/message`）到达时批量落地：流式输出进行中 token 计数冻结，step 结束时数百 token 一次性入账，进度呈 10% 级跳变（5%→10%→20%→30%）。东家裁定底层驱动数据改为当前轮次耗费的时间；回合总时长同样不可知，需一条过原点、先快后慢、x→∞ 时渐近 100% 永不到达的时间曲线。

#### 决策
进度按 y = t/(t+120)（t 为本回合已耗秒数，半衰期 120s）映射，整回合单一曲线、不区分 think/stream/tool 阶段；替代 C-005 中「阶段进度由阶段 + 输出 token 累计估计」一项，C-005 的数据源路线（客户端订阅快照、无自有路由）不变。单调性由函数本身保证，渲染层单调下限（progressFloor）、tool 冻结语义与思考基线（PROGRESS_THINK_BASE）随 token 驱动一并移除；回合切换由 turnTimings 新回合起点自然归零重计。token 计数与速率显示（R-01-009/AC-05）不受影响。

#### 被否方案及原因
- 指数时间曲线 1−e^(−t/τ)：尾部指数趋近，τ=60s 时 5 分钟即钉死 99% 呈假死，长回合看似卡住。
- 反正切 (2/π)·arctan(t/τ)：形态与有理曲线近似，但参数无半衰期式直觉语义，且多一次三角函数计算。
- 保留阶段权重的分段时间填充（think 爬升/stream 饱和/tool 冻结）：tool 冻结期间条停住，平滑性打折，且阶段权重本身是任意常数。
- token/时间混合（stream 仍按 token）：stream 阶段的跳变根因依旧存在。
