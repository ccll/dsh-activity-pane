# C-100 语义行排除路径登记 .dsh-plugin/ 生成物

日期: 2026-10-22

#### 上下文
AgentMap v4 的语义行数与累计审计窗口按 diff 增删合计计量；活动窗格客户端 bundle 是客户端源码经构建脚本生成的产物（产物文件头自述「应编辑源码而非本文件」，落点见 SOLUTION），其与源文件的一致性由 pre-commit 的 bundle 字节比对门禁保证。T-177 累计审计发现：窗口实测 332 语义行中该生成物占 59 行，同一改动被源码与 bundle 双计，使累计审计行数间隔（300）的触发数字虚高——剔除后窗口约 273，触发时点会推迟；而「语义行排除路径」参数未登记该目录，实现者在 task 证据行按「除生成物」口径自算，造成口径漂移（T-177 审计 N-3）。

#### 决策
将 `.dsh-plugin/` 登记进 CONVENTIONS「语义行排除路径」，生成物不参与语义行计数。

#### 被否方案及原因
- 不登记、继续手工在 task 证据里注明「除生成物」：口径落在文字而非机械参数，每个 task 都要重复声明，且 lint 实测与声明数字永远不一致（T-176 出现 132/235/228 三数并存），持续产出 warning 与审计摩擦。
- 改为对 bundle 只计一次（如跳过与源码内容相同的提交）：排除路径是既有机制的直接扩展，glob 参数一行可表达；修改计量引擎逻辑影响面大且需要上游 canonical 同步，不值得。

#### 影响面
R-01-008 · 窗格渲染与显示档位（间接：计量口径参数化）；AgentMap 本地参数（T-177）。登记后新窗口的触发统计不再含生成物行，源码与 bundle 一致性仍由 pre-commit 字节门禁独立保证。
