# C-040 等待双类差异化呈现：完成提醒改绿色成功语义、闪烁载体移至卡片末行（修订 C-037、翻案 C-028 否决的双色系）

日期: 2026-08-27

#### 上下文
C-037 落地后，两类等待卡的视觉呈现几乎同构：同为琥珀暖色卡面、标题圆点与徽标同频脉冲，仅靠徽标有无图标与文字区分。东家指出两种等待语义截然不同——提问/授权是「需要用户立即答复才能继续」，完成提醒是「任务已成功执行完毕、等后续指示」——用相同底色与相同位置的闪烁无法一眼分辨轻重缓急；且标题区闪烁只说明「这个会话有情况」，不指向该读哪行字。

#### 决策
- 紧迫度改由色彩语义承载：阻塞等待卡保持琥珀暖色卡面催促尽快响应；完成提醒卡改用绿色成功色系卡面（深暗绿底 + 绿描边光晕 + 绿状态点），表达任务成功执行完毕、不必抢答。
- 闪烁载体统一移至卡片末行：两类均以末行提示文字整体脉冲闪烁（dap-pulse 1.2s 同频）；阻塞等待卡的类型徽标移至末行行尾随文字同闪，标题状态点在两类下均静止不再闪烁。
- 完成提醒卡去掉「已完成」类型徽标；末行提示改为「本轮任务已完成，请给出新的指令，或将会话移入历史」，确认按钮文案由「知道了」改为「移入历史」（ack 写回与跨端同步行为不变）。
- 阻塞等待中待回复卡的末行提示改为第一条提问的标题（ask_user_question `questions[0].header`），无 header 时回落问题正文首行，再回落动作说明——提示即答案入口；待确认/待审查维持现有动作说明。
- 列头计数徽标（n/m）底色动态跟随等待构成：存在任一阻塞等待主会话时取琥珀，等待全部为完成提醒时取绿；脉冲门控（任一等待即脉冲）与频率映射不变（C-037 意图保留）。

#### 被否方案及原因
- 维持 C-037 完全同构呈现（仅靠徽标小字区分）：扫视场景下不可辨轻重缓急，东家实测判定不可接受，本决策的直接动因。
- 回退 C-028 的「完成提醒静止降噪」：静态呈现使完成提醒长期被忽略的教训见 C-037，本次保留闪烁注意力提醒，只换色彩语义与位置。
- C-028 曾否决的双色系「绿易与运行绿混淆」：运行卡的绿仅出现在进度百分比与时间线完成点的 5px 小元素上，而完成卡以整卡大面积暗绿底呈现，视觉量级不同不敢混淆；且东家主动要求成功=绿色的色彩语言，冲突前提（「等待=琥珀」单一主题）已被新需求取代。
- 计数徽标固定琥珀统示或固定绿：单色无法表达混合构成，会漏掉「有会话被卡住」这一最紧迫信号；跟随构成是最小正确方案。
