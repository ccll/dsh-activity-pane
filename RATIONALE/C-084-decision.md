# C-084 显示档位资源纪律以档位为唯一输入裁剪数据面与渲染面，不探测设备或网络

日期: 2026-10-08

#### 上下文
东家查证确认：三档显示档位仅为 CSS 呈现差异，后台数据通道（宿主 SSE、每可见会话 eventSource 日志窗口、冷会话日志分页深翻、模型目录读取）与渲染派生不随档位变化；移动网络与移动设备上带宽与运算负担因此与完整档相同，影响使用体验。东家立项要求档位驱动的资源节省，使紧凑/中间档在移动平台上产生实际价值。

#### 决策
新增 R-01-024 档位资源纪律：紧凑档不为不可见内容传输会话日志数据或构建其 DOM——主会话日志窗口不建立或保持、主会话日志分页深翻与无可见消费者的一次性模型目录读取不发起；轮内状态订阅、回合统计与完成确认通道、会话/工作区列表订阅、子代理日志窗口（承载标题行可见模型上下文）保持正常；中间/紧凑档不写进度行与 token 统计行、紧凑档不构建时间线内容。裁剪以档位为唯一输入，全平台生效；切回更高档位经既有渐进加载语义恢复。主会话日志窗口订阅与 liveness 订阅的生命周期拆分，拆窗不拆 liveness。

#### 被否方案及原因
- 按移动断点或网络状况探测后裁剪：触发条件依赖启发式与不可判定的环境判断，档位本身已是用户「只看概要」意图的直接表达，跟随档位行为可判定、跨刷新可复现。
- 中间档同步裁剪数据面：中间档仍显示最近卡预览行与时间线末行（R-01-021/AC-08），可见内容依赖既有全部数据通道，裁剪无收益空间；只做渲染层跳写。
- 一并断开空闲期 acks/busy SSE 通道（TODO 遗留想法）：完成提醒徽标的及时性权衡未经东家拍板，且与本需求的档位触发模型正交，维持 TODO 待议。
- 切回高档位时全量重建可见会话窗口（一次性并发洪峰）：沿用既有并发池上限 3 与渐进呈现逐卡就绪，避免移动网络下的重取高峰。
- 深翻默认无页数上限（完整/中间档既有张力）随本需求一并收敛：该张力独立于档位纪律存在，扩入本需求会放大行为变更面；保留现状另议。

#### 影响面
R-01-024、R-01-010/AC-09（档位限定注记） / 窗格渲染器、活动状态模型（T-157）
