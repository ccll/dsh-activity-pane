# C-068 历史会话采用客户端分批呈现而非 native 网络分页

日期: 2026-08-31

#### 上下文
当前 DSH `session.list` v1 会一次返回全部可见会话，`cursor` 仍是未实现的预留字段。东家希望历史区取消 24 小时与 20 条限制，首批显示最近 10 条，滚动到底部后继续浏览更早会话，同时降低首屏卡片与冷详情读取压力。

#### 决策
- 历史候选改为当前会话服务快照中符合既有过滤规则的全部非活动主会话，不再按时间窗口或条数截断。
- 本任务只在插件端维护历史分页：首批呈现 10 条，触底追加最多 10 条；历史卡片的 models/history 详情只对已呈现批次读取，继续复用既有并发池与失败重试。
- 历史排序继续采用精化后的最后活动时间。
  - 冷详情到达后允许按既有契约重新排序，相同活动时间以会话 id 作为稳定次序。
  - 列表元数据仍接受 native 全量快照。
- 不在本任务内引入虚拟列表或修改 DSH host/runtime；若全量列表传输成为可测量瓶颈，另立上游分页契约与一致性决策。

#### 被否方案及原因
- 现在直接推动 DSH `session.list` cursor 分页：当前接口与 host 实现尚未提供可用 cursor、`hasMore` 或快照一致性契约，会把本次 UI 需求扩大为跨仓库 API 迁移。
- 为保持跨页 `activityAt` 完全稳定而预读全部历史详情：会抵消分批详情加载的收益，并违反轻量常驻与按需读取边界。
- 同时引入虚拟列表：当前需求是首屏与详情渐进呈现，未有大规模 DOM 性能基线；先保留已呈现卡片，待真实规模证明需要后再拆分。

#### 影响面
R-01-010、R-01-019 · 活动状态模型、窗格渲染器
